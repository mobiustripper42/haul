## Summary
The app gets its own database user, `haul_app`, that can read and write the business tables, only read `audit_log`, has no rights on `_migrations`, cannot truncate or change schema, and can call `audit_event()`. One migration sets this up, including an automatic grant on every table made later, and the schema check fails the build if the app's rights ever drift. The riskiest [Lead] call: the migration creates `haul_app` itself (NOLOGIN) if absent, and the automatic grant binds to whichever user runs migrations — so every future migration must run as that same user.

## Job
The production app connects as a user that cannot rewrite the audit log or wipe a table.
