## How

There is no Haul history yet, so the rates come from the sibling repo muster: its session files
(`muster/.sessions-worktree/sessions/*.md`, on muster's orphan `sessions` branch) record `started`,
`ended` and `points` for each working session. 47 sessions have all three with a duration under
24 hours.

| Measure | Hours per point |
|---|---|
| All 47 sessions: 548 h for 568 pts | 0.97 |
| Median session | 0.96 |
| By month: June / July / August 2026 | 1.02 / 0.85 / 1.31 |
| Fastest quarter of sessions | 0.59 or better |
| Sessions clearing 10+ points (26 of them) | 0.70 |
| Best seven days, from 2026-07-05: 139 pts in 78 h | 0.56 |

- **Typical** uses ~1.0 h/pt.
- **Burst floor** uses muster's best week. Its 139 points match Phases 0–2 exactly, so it reads as
  "the whole Supper Club in one muster-grade week".
- **Overhead** adds 20–25% for work the points do not cover: design mockups, meetings and messages
  with the farm, chasing farm access, and reviewing pull requests. **This percentage is a guess,
  not a measurement.**
- Phase 3 and 4 points are Claude's analogy estimates from the phase descriptions in the spec
  (Phases section), not poker. The product builder (~13, admin screens in both designs) and the Square import (~8) are the
  largest pieces of Phase 3.

The hours are **wall-clock session time**, breaks included — not keyboard time. That is the
reasonable basis for billing, and it is why the velocity guide does not use hours as a progress
measure: it is a pricing input here, nothing more.

## Why it is not lower

- **Muster's burst was mid-project.** The domain core, ports and gate already existed and the tasks
  were well understood. Haul's Phase 0 builds all of that from nothing, and setup tasks run slowest.
- **Square is new ground.** Tasks 1.2, 1.4, 2.2, 2.3 and 2.13 are 37 points against an API no
  earlier repo has used. Muster's payment phases ran slower than its averages.
- **Not in the points:** design pauses at each screen, the farm's turnaround on answers and access
  (Square credentials, DNS), and production surprises.

## Reproducing the rates

Run from muster's sessions worktree:

```python
import glob, re, datetime as d, statistics as S
rows = []
for f in sorted(glob.glob('*.md')):
    s = open(f).read(3000)
    st = re.search(r'^started:\s*(\S+)', s, re.M)
    en = re.search(r'^ended:\s*(\S+)', s, re.M)
    pt = re.search(r'^points:\s*(\d+)', s, re.M)
    if not (st and en and pt):
        continue
    try:
        a = d.datetime.fromisoformat(st.group(1).replace('Z', '+00:00'))
        b = d.datetime.fromisoformat(en.group(1).replace('Z', '+00:00'))
    except ValueError:
        continue
    h = (b - a).total_seconds() / 3600
    if 0 < h < 24 and int(pt.group(1)) > 0:
        rows.append((a, h, int(pt.group(1))))
print(len(rows), 'sessions', sum(r[1] for r in rows) / sum(r[2] for r in rows), 'h/pt')
print('quartiles', S.quantiles(sorted(r[1] / r[2] for r in rows), n=4))
```
